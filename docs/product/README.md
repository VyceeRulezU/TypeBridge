# TypeBridge Knowledge Base

This directory contains the core documentation and specifications for TypeBridge. Reference these files to understand the product, architecture, design system, and technical constraints.

## Knowledge Index

| File | Coverage | When to Reference |
|------|----------|-------------------|
| [PRODUCT.md](./PRODUCT.md) | Vision, problem statement, v1 scope. | Onboarding, feature planning. |
| [ARCHITECTURE.md](./ARCHITECTURE.md) | System design, file structure, data flow. | Implementing new features or refactoring. |
| [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) | Tokens, CSS Modules, naming conventions. | Creating or updating UI components. |
| [BUILDERS.md](./BUILDERS.md) | Supported web builders, injection strategies. | Debugging builder-specific issues. |
| [USER_FLOW.md](./USER_FLOW.md) | User journeys, message schemas, state. | Implementing logic and state transitions. |
| [DECISIONS.md](./DECISIONS.md) | ADRs (Architectural Decision Records). | Understanding "why" certain tech choices were made. |
| [ROADMAP.md](./ROADMAP.md) | Future features and v1 locked scope. | Prioritizing work beyond the MVP. |
| [CHROME_STORE.md](./CHROME_STORE.md) | Submission checklist, permissions. | Preparing for production release. |

## Maintenance

Keep these files updated as the project evolves. Use ADRs in `DECISIONS.md` to document significant changes in direction.
